Sensors

Download schema

The sensors in an organization.

List sensors

GET
https://api.kaiterra.com/v2
/orgs/{org}/sensors

Lists the sensors in the organization that your API key can reach, sorted by ID.

ancestor is an optional filter. It selects every sensor under one building, floor, or space. Because it's a filter, one that matches nothing gives you an empty items, not an error. To look up specific sensors by ID, use GET /orgs/{org}/sensors/batch instead.

This collection supports both kinds of paging. With no paging parameters, you get the first cursor page. Pass page.next_cursor back as cursor to get the next one. Set limit to switch to offset paging, where page.total tells you the size of the collection.

List sensors › path Parameters

org
​string · required

The organization's ID, or the reserved word me for the organization your API key belongs to. A value that's neither me nor a UUID is a 400 that names org. The ID of any organization other than your own is a 403.

Example: me

List sensors › query Parameters

ancestor
​string · uuid

ID of any entity above the sensor, such as a building, floor, or space. Selects every sensor under it. An ID that isn't an entity in this organization is a 400.

cursor
​string

Pass the previous response's page.next_cursor here to continue where it left off. The value is opaque. You can't combine it with limit or offset.

limit
​integer · min: 1 · max: 250

Switches to offset paging, with this many items per page, from 1 to 250. The response then carries page.total.

offset
​integer · min: 0

How many items to skip. Only valid together with limit. If you pass limit without offset, you get the first page. An offset past the end of the collection isn't an error. You get an empty items and the current total.

Get sensors by ID

GET
https://api.kaiterra.com/v2
/orgs/{org}/sensors/batch

Returns exactly one sensor per ID, in the order you gave them.

This is a lookup, not a filter. On success, the response has every sensor the request named and nothing else. That means duplicate IDs, unknown IDs, and sensors your API key can't reach are all errors. Duplicate IDs are a 400. Unknown IDs and sensors your API key can't reach are a 404, which doesn't say whether the sensor exists elsewhere. Either response names each offending value against the id parameter.

The response isn't paged, because the request already fixes the number of items. There's no page, and the list parameters ancestor, cursor, limit, and offset are rejected.

Get sensors by ID › path Parameters

org
​string · required

The organization's ID, or the reserved word me for the organization your API key belongs to. A value that's neither me nor a UUID is a 400 that names org. The ID of any organization other than your own is a 403.

Example: me
